# 薄书使用指南

[返回首页](../README.md) · [实现与隐私](implementation.md) · [系列书目](catalog-series.md)

## 安装与双击启动

1. 下载并解压薄书到可写目录。Windows 双击 **`start.bat`**；Linux 执行 **`sh start.sh`**，或允许 `ThinBook.desktop` 启动。
2. 启动器自动检测系统与架构、Node.js、npm、项目依赖及目录权限。缺少 Node.js/npm 或版本过低时，从 [Node.js 官方下载源](https://nodejs.org/en/download) 安装便携版 Node.js 24 LTS，校验 SHA-256 后自动配置本次启动的路径；缺失或损坏的依赖自动安装修复。
3. 先检查 DSH Web 是否已运行：已有服务时直接接入，通过配置热加载挂载薄书，不再启动第二个 DSH。没有运行中的服务时，自动检查 DSH 最新版，缺少则安装，有更新则升级。端口被占用时自动换用空闲端口，并记住本次地址供重复启动复用。首次配置需要联网，已有完整环境后会优先复用。
4. 已有 DSH API Key 时直接阅读。首次配置：Windows 双击 **`configure.bat`**，Linux 执行 **`sh start.sh --dsh web`**，在 DSH 中填写自己的 DeepSeek API Key 并选择官方默认模型，然后回到薄书点击「刷新配置」。API Key 需要用户提供，环境安装不会生成或覆盖密钥。

自动安装支持 Windows / Linux 的 x64 和 arm64；Linux 需具备常见的 `sh`、`tar`、`curl` 或 `wget`，以及 SHA-256 校验工具。Node.js/npm 位于项目 `.runtime/node/current/`，无需管理员权限。PATH 和本机代理绕过仅对本次启动生效，已有系统安装会保留。

没有现有 DSH Web 时，启动器才在后台运行 `dsh web --no-open`；已有服务时直接复用并加载薄书插件。**双击启动只打开薄书页面，不打开 DSH Web 页面**，无需提前手动运行 DSH。只有主动运行首次配置入口时才打开 DSH 页面。薄书复用 DSH 的 Key 和默认模型，不要求重复填写 Key。

自动安装位于 `$DSH_HOME/runtimes/thinbook/current/`（默认 `~/.dsh/runtimes/thinbook/current/`），不需要管理员权限，不覆盖系统全局 DSH。安装使用临时目录，校验后才启用。若更新检查失败但已有可用 DSH，会显示提示并使用现有版本；首次安装需要网络。

默认访问 **<http://127.0.0.1:3210>**；若自动避让端口，以打开的页面和终端打印地址为准。只有启动器自己创建 DSH 时，关闭启动终端才会停止该服务。复用原有 DSH 时，启动器打开薄书后退出，原服务继续运行。重复双击复用现有薄书，不会使 `whereto` 等独占端口插件重复加载。

已安装 Node.js 的用户也可运行 `npm start`，同样会自动检测并配置依赖。开发时可运行 `npm run dev`。使用自定义 DSH 安装时，将 `DSH_BIN` 设置为 CLI 的绝对文件路径；Windows 自定义启动器可直接指定 `…/dsh/lib/bin.js`。

## 安装到 DSH Web 插件列表

如果希望让薄书随日常 DSH Web 一起运行，可在项目目录执行：

```sh
npm run dsh -- plugin --profile web add /absolute/path/to/thinbook
npm run dsh -- web --no-open
```

将路径替换为实际项目目录，包含空格时加引号。已有全局 DSH 时也可直接使用 `dsh plugin` 和 `dsh web`。该方式从插件包的 bundle 清单加载薄书；在浏览器访问 <http://127.0.0.1:3210> 即可。插件不会自行打开任何页面。双击启动方式直接加载本地插件，无需先执行插件安装命令。

这两种方式均使用同一个 DSH `web` profile。首次启动会在该 profile 的 `cordis.patch.yml` 中添加带标记的薄书配置块，保留其他插件配置；DSH 默认启用的 HMR 会自动加载薄书，后续更新只替换此配置块。启动锁避免同时双击创建多个 DSH。

## 快速使用

1. 打开「模型设置」可查看 DSH 当前默认模型。若调整了 DSH 的 Key 或模型，点击「刷新配置」继续阅读。当前支持 DSH 的 DeepSeek 官方 API Key 路由。
2. 搜索或选择一本书，选择 **5 / 10 / 20 分钟**。输入系列名或点击书籍详情中的系列入口，可按顺序查看同系列书籍。有原文时可粘贴或导入 UTF-8 TXT / Markdown，再开始读薄。
3. 完成后自动缓存，相同书籍、篇幅、模型、原文和规则再次请求会优先使用缓存，**缓存读取不调用 API**。「最近阅读」可打开已有缓存。页面提供费用参考估算与 Markdown 导出。
4. 手机或平板连接同一局域网，打开薄书主页展示的地址即可使用。页面与终端只显示一个优选地址：优先使用以太网适配器的 `192.168.*` IPv4，跳过 VMware、WSL、Docker、VPN 等虚拟网卡；没有此类以太网地址时，再选择其他实际局域网地址。端口以当前服务为准。其他设备共用主机的 DSH 模型和薄书缓存。

双击启动的缓存仍放在项目 `.local/readings/`。随 DSH 安装的插件默认放在 `$DSH_HOME/thinbook/.local/readings/`（未设置 `DSH_HOME` 时为 `~/.dsh/thinbook/.local/readings/`）。旧版 `.local/config.json` 不再读取或写入；请在 DSH 中配置好 Key 后自行删除旧配置文件。旧缓存仍可从「最近阅读」打开，新生成按新缓存规则保存。

API 生成与联网取材会产生 DeepSeek 费用；页面金额为参考估算，实际以账户账单为准。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 已有 DSH，但薄书热加载超时 | 检查原服务的 HMR 是否启用，必要时重启原 DSH；启动器不会回退为重复启动第二个服务 |
| DSH 自动安装或升级失败 | 检查网络、npm 和 DSH 安装目录写入权限，然后重新双击启动；自定义安装可使用 `DSH_BIN` |
| 提示未配置 Key | 在 DSH 中配置 DeepSeek API Key，并选择 DeepSeek 官方默认模型，然后在薄书刷新配置 |
| 更新后仍显示旧的「DSH 未完成提炼」提示 | 重启当前 DSH Web 服务，再双击薄书并刷新页面；已运行的宿主可能仍加载旧版插件代码 |
| 模型请求失败 | 按页面提示分别检查认证、账户额度、网络或输出长度；输出达到上限时选择较短阅读时长或分段提供原文 |
| 联网工具初始化失败 | 重启当前 DSH Web 加载最新插件；如果仅搜索服务或网络不可用，可补充原文后提炼 |
| 环境自动配置失败 | 检查下载网络与项目写入权限，重新启动会重试；无需手动修改系统 PATH |
| 3210 端口被占用 | 自动选择空闲端口；以打开页面和终端打印地址为准，也可通过 `PORT` 指定首选端口 |
| 联网找书失败 | 检查代理和网络；远程书库不可达时会明确返回本地匹配，仍可自选书名与作者 |
| 手机打不开页面 | 确认主机正在运行、设备处于同一局域网；Windows 防火墙需允许专用网络的 Node.js / TCP 3210，检查路由器客户端隔离 |
| 仅允许本机访问 | 设置 `HOST=127.0.0.1` 后启动 |
| 未生成可靠正文 | 可补充原文或增加阅读时长；系统不会用虚构细节填补资料缺口 |

实现与隐私细节见 [技术文档](implementation.md)，系列范围与核对来源见 [书目说明](catalog-series.md)。维护者使用 `npm ci` 安装开发用 DSH，再在 Node.js 24.5+ 下运行 `npm test`。测试使用隔离配置和离线模型，不调用付费 API。
