# 薄书使用指南

[返回首页](../README.md) · [实现与隐私](implementation.md) · [系列书目](catalog-series.md)

## 安装与双击启动

1. 下载并解压薄书到可写目录。Windows 双击 **`start.bat`**；Linux 执行 **`sh start.sh`**，或允许 `ThinBook.desktop` 启动。
2. 启动器自动检测系统与架构、Node.js、npm、项目依赖及目录权限。缺少 Node.js/npm 或版本过低时，从 [Node.js 官方下载源](https://nodejs.org/en/download) 安装便携版 Node.js 24 LTS，校验 SHA-256 后自动配置本次启动的路径；缺失或损坏的依赖自动安装修复。
3. 先检查 DSH Web 是否已运行：已有服务时直接接入，通过配置热加载挂载薄书，不再启动第二个 DSH。没有运行中的服务时，直接使用 PATH 中已安装的 DSH，不查询最新版，不自动安装或升级。端口被占用时自动换用空闲端口，并记住本次地址供重复启动复用。首次配置需要联网，已有完整环境后会优先复用。
4. 已有 DSH API Key 时直接阅读。首次配置：Windows 双击 **`configure.bat`**，Linux 执行 **`sh start.sh --dsh web`**，在 DSH 中填写自己的 DeepSeek API Key 并选择官方默认模型，然后回到薄书点击「刷新配置」。API Key 需要用户提供，环境安装不会生成或覆盖密钥。

自动安装支持 Windows / Linux 的 x64 和 arm64；Linux 需具备常见的 `sh`、`tar`、`curl` 或 `wget`，以及 SHA-256 校验工具。Node.js/npm 位于项目 `.runtime/node/current/`，无需管理员权限。PATH 和本机代理绕过仅对本次启动生效，已有系统安装会保留。

没有现有 DSH Web 时，启动器才在后台运行 `dsh web --no-open`；已有服务时直接复用并加载薄书插件。**双击启动只打开薄书页面，不打开 DSH Web 页面**，无需提前手动运行 DSH。只有主动运行首次配置入口时才打开 DSH 页面。薄书复用 DSH 的 Key 和默认模型，不要求重复填写 Key。

DSH 优先复用 PATH 中的现有安装；PATH 未提供时，可使用已有的 `$DSH_HOME/runtimes/thinbook/current/`。启动检查只确认是否已经安装并能运行；未找到时提示先安装一次或设置 `DSH_BIN`。不会下载新版本或改动其他项目的 DSH。

页面默认独立监听 `0.0.0.0:3102`，本机访问 `http://127.0.0.1:3102/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `THINBOOK_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。

已安装 Node.js 的用户也可运行 `npm start`，同样会自动检测并配置依赖。开发时可运行 `npm run dev`。使用自定义 DSH 安装时，将 `DSH_BIN` 设置为 CLI 的绝对文件路径；Windows 自定义启动器可直接指定 `…/dsh/lib/bin.js`。

## 安装到 DSH Web 插件列表

如果希望让薄书随日常 DSH Web 一起运行，可在项目目录执行：

```sh
npm run dsh -- plugin --profile web add /absolute/path/to/thinbook
npm run dsh -- web --no-open
```

将路径替换为实际项目目录，包含空格时加引号。已有全局 DSH 时也可直接使用 `dsh plugin` 和 `dsh web`。该方式从插件包的 bundle 清单加载薄书；在浏览器访问 <http://127.0.0.1:3102/> 即可。插件不会自行打开任何页面。双击启动会自动通过现有 DSH 将本项目登记为本地 bundle，无需提前手动安装。插件栏会显示「薄书 · DSH Web 阅读工作室」，可以启停或卸载。

这两种方式均使用同一个 DSH `web` profile。首次启动会登记 `dependencies.thinbook` 与 `dsh.profile.bundles`，并在该 profile 的 `cordis.patch.yml` 中添加仅配置 `dataRoot` 的薄书覆盖块；旧版文件入口会自动迁移并保留数据目录，保留其他插件配置；DSH 默认启用的 HMR 会自动加载薄书，后续更新只替换此配置块。启动锁避免同时双击创建多个 DSH。

## 快速使用

1. 打开「模型设置」可查看 DSH 当前默认模型。若调整了 DSH 的 Key 或模型，点击「刷新配置」继续阅读。当前支持 DSH 的 DeepSeek 官方 API Key 路由。
2. 搜索或选择一本书，选择 **5 / 10 / 20 分钟**。输入系列名或点击书籍详情中的系列入口，可按顺序查看同系列书籍。可在每本书的卡片点击「＋ 选择原文」，关联本地 UTF-8 TXT / Markdown（最多 60 万字），在详情中确认是否完整原文，再开始读薄；原文按书名与作者保存，后续打开仍优先使用。详情也支持导入或粘贴原文。长原文会自动分段提炼、分层整合，保留原有章节框架；无需为上下文窗口手动拆书。未选择本地原文时，DSH 先检索并抓取网络原文；网络原文仅覆盖部分章节时，保留已读原文压缩，并以可靠网页资料补齐其余主要部分；完全未获得可读取原文时回退网页资料，并在阅读页标明取材方式和限制。未提供本地原文、且 DSH 实际读到完整网络原文时，会尝试缓存；阅读页末尾可点击「查看缓存原文」，同时提供来源链接。只有部分原文时仅显示原文链接；没有原文则不显示原文入口。
3. 正文按段显示，生成下一段时可以先读前面的内容；达到单次输出上限会自动接续，页面持续追加，全部完成后才自动缓存。可随时点击「停止生成」。相同书籍、篇幅、模型、原文和规则再次请求会优先使用缓存，**缓存读取不调用 API**。「最近阅读」可打开已有缓存。页面提供费用参考估算与 Markdown 导出。阅读页点击「重新读薄」会按当前模型和最新规则重新生成，沿用原书与时长，优先使用当前关联原文，其次复用原阅读保存的原文；没有原文则重新执行原文检索和资料回退，成功后覆盖原阅读并重置进度。失败或取消保留旧内容。导入的原文保存在本机。重新生成会调用 API 并产生费用。
4. 页面默认独立监听 `0.0.0.0:3102`，本机访问 `http://127.0.0.1:3102/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `THINBOOK_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。

双击启动的缓存仍放在项目 `.local/readings/`。随 DSH 安装的插件默认放在 `$DSH_HOME/thinbook/.local/readings/`（未设置 `DSH_HOME` 时为 `~/.dsh/thinbook/.local/readings/`）。旧版 `.local/config.json` 不再读取或写入；请在 DSH 中配置好 Key 后自行删除旧配置文件。旧缓存仍可从「最近阅读」打开，新生成按新缓存规则保存。

API 生成与联网取材会产生 DeepSeek 费用；页面金额为参考估算，实际以账户账单为准。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 能加载薄书但插件栏不显示 | 旧版只插入文件入口；新版启动器会登记正式 bundle，保留数据并迁移旧入口，之后刷新插件栏 |
| 已有 DSH，但薄书热加载超时 | 检查原服务的 HMR 是否启用，必要时重启原 DSH；启动器不会回退为重复启动第二个服务 |
| 未找到已安装的 DSH | 将已有 DSH 加入 PATH，或用 `DSH_BIN` 指定已有入口；启动器不查询最新版或自动下载 |
| 提示未配置 Key | 在 DSH 中配置 DeepSeek API Key，并选择 DeepSeek 官方默认模型，然后在薄书刷新配置 |
| 更新后仍显示旧的「DSH 未完成提炼」提示 | 重启当前 DSH Web 服务，再双击薄书并刷新页面；已运行的宿主可能仍加载旧版插件代码 |
| 模型请求失败 | 按页面提示分别检查认证、账户额度、网络或输出长度；上下文超限会自动拆分与压缩；若仍失败可切换更大上下文的模型。输出达到上限会自动接续；若其他错误中断，已显示内容仍可阅读，完成前不会写入完整缓存 |
| 联网工具初始化失败 | 重启当前 DSH Web 加载最新插件；如果仅搜索服务或网络不可用，可补充原文后提炼 |
| 章节与来源暂未对应 | 会自动补核对来源并修复来源表，保留已显示正文；只有反复核验仍失败才停止。真实缺失的证据仍需补查或补充原文 |
| 环境自动配置失败 | 检查下载网络与项目写入权限，重新启动会重试；无需手动修改系统 PATH |
| 3210 端口被占用 | 自动选择空闲端口；以打开页面和终端打印地址为准，也可通过 `PORT` 指定首选端口 |
| 联网找书失败 | 检查代理和网络；远程书库不可达时会明确返回本地匹配，仍可自选书名与作者 |
| 手机打不开页面 | 确认主机正在运行、设备处于同一局域网；Windows 防火墙需允许专用网络的 Node.js / TCP 3210，检查路由器客户端隔离 |
| 仅允许本机访问 | 设置 `HOST=127.0.0.1` 后启动 |
| 未生成可靠正文 | 可补充原文或增加阅读时长；系统不会用虚构细节填补资料缺口 |

实现与隐私细节见 [技术文档](implementation.md)，系列范围与核对来源见 [书目说明](catalog-series.md)。维护者使用 `npm ci` 安装开发用 DSH，再在 Node.js 24.5+ 下运行 `npm test`。测试使用隔离配置和离线模型，不调用付费 API。
