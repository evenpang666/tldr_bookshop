# 薄书：DSH 插件实现

使用入口见 [README](../README.md)。启动时使用 npm `latest` 版本的 DSH，不设置宿主兼容版本限制。

## 插件与启动

`package.json` 导出 `plugin/index.mjs`，并声明 `dsh.bundle.patch` 指向 `cordis.patch.yml`。通过 `dsh plugin --profile web add <path>` 安装后，DSH 根据 bundle 加载插件。插件依赖宿主的 `agents`、`tools`、`systemPrompt`、`web`、`credentials`、`agentDefaultModel` 、`profileContext`、`webServer` 和 `connection` 服务。

双击脚本先通过 `scripts/bootstrap-node.sh` 或 `scripts/bootstrap-node.ps1` 检测 Node.js/npm。若缺少或 Node 低于 24.5，则根据系统与架构下载官方 Node.js 24 LTS 的便携压缩包，与官方 `SHASUMS256.txt` 比对 SHA-256，解压后验证 Node/npm 可运行，再启用项目 `.runtime/node/current/`。复用可用系统环境，不需要管理员权限，不改系统 PATH。

随后 `scripts/environment.mjs` 配置本次子进程的 PATH、`NODE_USE_ENV_PROXY`、本机地址的 `NO_PROXY` / `no_proxy`，保留已有代理值与绕过地址；创建并验证缓存和运行目录可写。校验生产依赖的版本及入口，发现缺失或损坏时执行 `npm ci --omit=dev`；npm 安装包没有 lockfile 时改用 `npm install --omit=dev --no-package-lock`。`npm start`、`npm run dev` 和 `npm run dsh` 也使用同一入口；Node/npm 不可用时转交平台 bootstrap 后重新启动。

`scripts/launch.mjs` 先检查 DSH 最低版本，再读取当前 DSH_HOME 的薄书服务记录 `<home>/thinbook/host.json`，检查记录进程和健康接口，再检测当前 DSH Web 进程。Linux 仅检查同用户的 DSH CLI 进程及其 `DSH_HOME`，区分其他 home 下的实例；Windows 使用系统进程查询，macOS 使用 `ps`。不会把 SDK、配置 dump 或包管理命令当作 Web 服务。

通过 `<home>/.thinbook-start.lock` 串行化同一 home 的启动。通过现有 DSH 的 `plugin --profile web add link:<项目目录>` 正式登记依赖及 bundle，使插件管理页可以列出薄书。复用共享 profile 的 pnpm 主版本与 store，不另装 DSH。旧版托管块中的文件 `insert` 会迁移为对 bundle 行的配置覆盖，保留原 `dataRoot`；注册失败时恢复旧块。随后为当前 `web` profile 的 `cordis.patch.yml` 追加带标记的薄书配置覆盖块，其他 YAML 保持原样，后续更新只替换此块；原文件为 JSON 列表时转成等价的 YAML 条目。文件以临时文件加重命名更新，写入前检查是否被其他进程修改。DSH 默认 HMR 观察该文件，因此已有 Web 服务可直接热加载薄书；其他插件不会重新创建，不会重复加载其他项目。

只有没有运行中的 DSH Web 时，才检查已有运行时，通过官方 config dump 初始化 profile（不启动 Web），写入薄书配置，并执行：

```text
dsh --profile web --no-open --host 127.0.0.1 --port 3080
```

启动前再次检查进程，避免配置过程中外部已启动 DSH。已有服务未能热加载时返回 HMR 检查提示，不回退为第二个 DSH。复用服务时立即打开薄书并结束启动器，不发送停止信号；自己创建的 DSH 才由该启动器管理退出。`npm run dsh -- web` 与首次配置入口也复用已运行的服务。

页面默认独立监听 `0.0.0.0:3102`，本机访问 `http://127.0.0.1:3102/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `THINBOOK_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。
DSH 是可选 peer 宿主和开发依赖，生产依赖只有 Undici。`DSH_BIN` 可覆盖 CLI 查找，Windows npm shim 解析到 JS 入口后直接运行，避免 shell 路径转义。
每次启动先通过 `scripts/dsh-version.mjs` 检查 DSH ≥ 0.2.0-rc.2，包括复用已运行服务的分支。缺失或过低时，在 `$DSH_HOME/runtimes/web/versions/0.2.0-rc.2` 暂存安装、校验后发布并切换入口；失败保留原安装。注册记录按插件单独保存，DSH 版本变化后调用官方命令重新登记，成功后才更新记录。符合要求时不查询 npm，也不降级新版。已有旧进程需要重启以加载新运行环境。

`npm run dsh -- <参数>` 提供已有环境检测的 CLI 入口，便于管理宿主。无全局 Node/npm 时，Windows 使用 `configure.bat`、Linux 使用 `sh start.sh --dsh web` 配置 API Key，或进行插件管理。普通双击仍使用 `--no-open`，不会打开 DSH Web。

## 模型与凭据

`plugin/index.mjs` 每次通过 `agentDefaultModel.currentSelection()` 读取模型，通过 `credentials.describe('DEEPSEEK_API_KEY')` 检查配置状态。薄书不解析 DSH 的凭据文件、不读取原始 Key、不将密钥注入子进程，也不保存 `.local/config.json`。DSH 按自己的凭据规则解析与更新 Key。当前入口仅接受 `deepseek-official` 默认路由。

网页只得到模型、provider 和配置是否就绪。旧版设置与测试 Key 接口拒绝写入；设置弹窗只提供配置状态和刷新。旧浏览器中的薄书 Key 会被清除；旧项目配置文件不自动迁移或删除。

`harness/reader.mjs` 使用宿主 `ctx.agents.create()` 为每篇阅读创建作用域独立的会话（长原文使用多个隔离会话），指定 provider、model、reasoningEffort 与输出上限。在发布前的 setup 中：

- 排除继承的工具，仅在该会话注册官方 `web_search` 和 `web_fetch`，使用 native 工具模式。
- 将 `.dsh/skills/thin-book/SKILL.md` 嵌入完整系统提示，抑制无关工作目录上下文。
- 观察该会话工具调用并提供进度。原文查找最多 12 次联网调用、资料补全与正文生成最多 16 次、两轮来源修复共用 4 次；失败的实际请求同样占用预算，分页与上下文恢复不重置预算。用完后在提示组装时隐藏联网工具，在执行前拦截同批超额调用，要求模型整理已取得材料继续当前阶段，保留成功工具记录与正文，不再因累计超限取消整篇提炼。预算拦截以 `WEB_BUDGET` 标记，与联网故障区分；最终仍须通过原有来源与章节核验。

官方工具和 `createUserMessage` 从 `profileContext.installAnchor` 对应的 DSH 安装解析，避免项目依赖提供另一套服务。向 `followup()` 提交前，通过该工厂生成带有稳定 ID、`role: user` 和来源的不可变消息；直接传入仅有 content/source 的对象会导致真实请求适配器序列化失败。用户断开连接、取消或超时，仅取消本次阅读拥有的会话；普通阅读时限为 12 分钟，长原文按预计分段数量增加处理时限。最终始终 dispose 自己持有的全部 AgentHandle，不结束共享 DSH。

每个阅读会话通过 `await agentCtx.plugin(webTools, options)` 挂载官方联网工具，完成 Config 校验、`web` 等服务注入和工具作用域注册后再发布会话。直接调用模块的 `apply()` 会绕过依赖注入，导致工具已列出但执行时报 `cannot get property "web" without inject`。

`lib/reading-segments.mjs` 对超过 16000 字符的本地原文预先自动切分，优先在段落或句界断开，所有连续范围无遗漏、无重复。各段使用隔离上下文压缩，保留章节、人物、论证、转折与结局；结构化上下文错误触发受影响片段减半重试，最小片段 500 字符。摘要过长时分层压缩，再用新会话整合，若整合上下文不足则继续缩减摘要。运行时验证原始范围 ID 全部按序覆盖、原文章节标题在最终正文中全部按序出现；缺段缺章结果不写入缓存，语义完整性仍依赖模型按 skill 保留各段实质内容。没有编号的章节标题可由分段模型识别，但须核验原文中确实独立成行。

较短原文遇到 `CONTEXT_WINDOW_EXCEEDED` 或 HTTP 413 时同样自动进入分段流程。联网会话因累积抓取材料超限时，将已成功取得的材料分段压缩后用新会话继续当前阶段，保留原始工具证据与来源归属；最多恢复两次，工具已截断而未取得的正文不冒充已读。分段、分层、整合与恢复的费用按全部会话汇总；取消会停止后续分段。

`lib/reading-output.mjs` 将最终正文改为分页协议：每次新增约 800–1200 字的 `bodyChunk`，`done: false` 时自动请求下一页，最后一页交付整篇来源、附注和覆盖元数据。运行时拼接为原有完整阅读 JSON，仍进行来源、章节与分段覆盖校验。若单次响应以 `max-tokens` 结束，保留已收到字符并接续未闭合 JSON（包括中断的转义）；已有页面在上下文压缩后继续保留。空响应、重复页面或无法修复的 JSON 会停止，单条 JSON 最多接续 8 次、每阶段最多请求 64 次，避免无限调用。

生成过程中通过 NDJSON `partial` 事件发送完整正文快照，网页替换快照避免重复追加，并保持阅读位置。草稿明确标记未完成，不写浏览器历史或磁盘缓存，不启用完整导出。只有最终核验成功才发送 `result` 并保存；首次生成失败后已显示内容仍可读并可重新尝试，重新读薄失败或取消仍保留旧完整阅读。

混合取材的章节来源表使用取材阶段生成的固定 `sectionId`、范围名和来源类型，避免正文标题缩写、拆章造成逐字匹配失败。兼容旧模型只返回名称，匹配时仅忽略排版和带实际标题的章节编号，不模糊合并不同范围。分页元数据按标识合并章节来源、按 URL 合并来源链接，最后一页不会丢失前页记录。全篇核验若发现缺项或来源不实，自动执行最多两轮 `[COVERAGE_REPAIR]`，仅补查来源和修复元数据，保留正文与已显示进度；新增检索记录计入真实来源验证与费用。修复响应中的正文不采纳，仍须通过原有原文抓取、至少两条补充资料、章节归属校验后才能保存；反复失败会停止，不能用伪造映射绕过核验。

来源修复收到逐条错误（章节标识、来源类型、不匹配 URL）以及取材阶段成功抓取页面、资料阶段实际取得来源的清单。若取材模型只登记目录页、最终引用实际已读的章节页，可显式返回 `originals` 完整纠正清单；运行时仅接受取材阶段成功抓取的 URL，并继续按固定章节范围校验，不会自动将候选页面、目录、搜索摘要、失败请求或资料阶段新增页面提升为已读原文。混合阅读始终保留部分原文标记，不能借修复变为完整原文。

修复元数据按章节标识（兼容同范围名称）和来源 URL 合并，局部补丁不覆盖其他已核验条目与正文；只有补丁覆盖全部固定范围时，才替换旧章节表并清理陈旧条目。来源列表先去重，混合阅读最多保留 128 条，避免旧 16 条上限截掉已实际引用的章节链接；所有来源仍须来自真实工具证据。取材规则要求逐页登记正文，出版说明、目录、纪年表等不作为必须补写的正文缺章。

提炼结束时检查结构化的 `turn/end.reason` 和 `LlmFailure.code/status`，分别提示认证、额度、限流、传输、模型配置等原因。`lib/reading-error.mjs` 只返回固定提示，不将提供方原始错误正文或凭据暴露到网页；失败或未接续完成的结果不会写入缓存。

会话日志和模型请求由 DSH 自身管理，遵循 DSH 的持久化和隐私设置。用户导入的原文会进入模型请求及 DSH 会话日志，不能再按旧 SDK 方案声称临时日志会立即删除。

原生适配器的离线回归保留真实 DSH 提供方、请求序列化和 SSE 解码，只将 HTTP 边界替换为模拟响应。无原文场景实际执行官方 `web_search` 和 `web_fetch`，经 DSH `web` 服务调用模拟搜索与抓取提供方，核验工具结果、来源元数据及最终正文；同时覆盖联网服务错误、依赖注入失败、资料不足、认证失败、额度不足、传输异常与输出超限后的成功接续，确认失败结果不缓存、提供方错误原文不返回网页。测试环境显式安装 DSH 的可选开发 peer `dsh-agent-preset-registry`，确保 npm 的开发依赖布局中请求扩展可正确解析。

## 缓存与费用

`lib/storage.mjs` 只负责磁盘缓存，以临时文件加重命名原子写入，目录 0700、文件 0600（Windows 遵循目录 ACL）。缓存身份包含书名、作者、provider、模型、reasoningEffort、阅读时长、原文哈希、完整原文标记、skill 哈希及 schema 版本。

双击默认复用项目 `.local/readings/`；常驻安装默认使用 `<DSH_HOME>/thinbook/.local/readings/`。可通过插件的 `dataRoot` 配置更换缓存根目录。旧版缓存仍可读取，新缓存身份不会与旧规则混用。书架、字号和进度保存在各设备浏览器。

缓存命中不调用模型；阅读页「重新读薄」发送 `force: true` 与 `replaceCacheId`，使用原缓存的书目与时长，优先使用当前书籍关联原文，其次复用原缓存的取材输入，再按当前模型与 skill 重新生成。新缓存以原子写入落盘后才清理不同身份的旧缓存；失败或取消时保留旧内容，同一替换目标与新缓存身份都加锁防止并发重复。导入原文与完整原文标记保存在磁盘缓存的 `generationInput` 中，该字段不返回阅读 API 或浏览器历史；原缓存没有可用原文时重新执行网络原文检索及资料回退。重新生成会再次计费。原生成费用留在缓存，读取缓存另标本次 API 费用为零。费用按会话中的 `assistant/message.usage` 估算，搜索额外用量仍是参考假设。价格快照在 `lib/cost.mjs`，不是实时账单。

未提供本地原文时，`lib/retrieved-original.mjs` 只从经取材阶段确认的原文 URL 对应的成功 `web_fetch` 工具记录提取文本。完整原文且每个原文页面都有未截断的实际文本时，将 `original.pages` 随阅读原子写入 `.local/readings/`，同时记录 `original.links`；部分原文只保存链接，不保存正文副本，无原文不创建该字段。缓存内容是工具实际返回的页面文本，移除 DSH 固定输出头，不使用模型重写、摘要或补全内容充作原文。

常规阅读 API 的 `publicReading()` 仅返回原文链接、完整性、缓存状态和字数，不向浏览器历史塞入全文。`GET /api/readings/:id/original` 在完整缓存存在时才按需返回页面文本，部分或缺失原文返回 404；访问权限与阅读 API 相同。阅读页显示「查看缓存原文」及来源链接，原文弹窗以转义后的纯文本呈现。写入失败时保留来源链接并关闭缓存查看入口；旧阅读没有此字段时不显示原文区域。

## 网络与内容边界

书目检索优先 Open Library，失败或无结果时尝试 Google Books。`lib/network.mjs` 使用 Undici 环境代理，代理失败时尝试直连，不关闭 TLS 校验。远程书库全不可达时明确降级为本地匹配。

本地原文以书名与作者的哈希关联，保存在 `.local/sources/`，可从书籍卡片或详情选择 UTF-8 TXT / Markdown，最多 60 万字。`POST /api/book-sources` 校验并保存正文，bootstrap 只返回书目、文件名、字数与完整性元数据。生成依次使用显式粘贴的原文、当前关联原文、重新生成时的历史原文；本地原文存在时不为阅读会话注册联网工具。

没有本地原文时，在同一个 DSH 会话执行两个受控阶段：先 `[ORIGINAL_DISCOVERY]` 搜索并抓取原文候选，校验其 URL 确有成功的 `web_fetch` 记录；若取得完整原文，下一轮只据原文压缩，单个已读原文来源即可。完整性由模型识别及抓取工具的 `truncated` 共同决定，截断或仅部分可读时进入 `[MIXED_COMPLETION]`：保留已读原文部分，另行检索至少两条不同于原文页面的可靠资料，补齐原文缺失章节，按全书主要框架连续生成。取材阶段返回 `coveredSections` 和 `missingSections`，成品 `coverageMap` 逐部分列出 original/reference 与实际 URL，运行时验证缺失部分均有资料条目、引用来自真实检索结果。混合成品标为“原文与资料综合提炼”，末尾小字显示逐部分取材方式，导出也保留。若无可读取原文，下一轮进入 `[REFERENCE_FALLBACK]` 另行搜索非原文资料，至少核验两条该阶段实际检索来源，并由运行时追加资料回退说明。`sourceMode` 分为 `local-original`、`web-original`、`web-mixed` 和 `web-reference`，界面显示取材方式；`basis` 由运行时决定，忽略模型自行声称的原文标记。此校验能确认检索与抓取行为，原文内容分类、事实与写作质量仍依赖模型判断。正文按原文章节框架和展开顺序压缩细节，保留叙述人称、笔墨与写作风格；小说保留主线与结局，非虚构直接展开命题、论证及边界。书籍介绍、作者背景和评价与正文分离，存入可为空的 `notes` 纯文本字段，在正文末尾以 12px 小字显示，Markdown 导出时以转义后的 `<small>` 附注保留。旧缓存缺少该字段时不显示附注。资料回退可使用可靠梗概、研究和导读中支持的内容；材料过少时提示缺口，不用简介凑字数或伪造正文。skill 内容变化会改变新生成请求的缓存身份，旧阅读仍可从历史打开。

页面默认独立监听 `0.0.0.0:3102`，本机访问 `http://127.0.0.1:3102/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `THINBOOK_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。

`lib/network.mjs` 统一生成页面与终端的局域网链接，仅展示一个优选地址：以太网 `192.168.*` 优先，其次为其他 `192.168.*`、其他以太网私有地址及其他私有地址。排除虚拟网卡和 VPN；没有合适地址时不展示链接。完整网卡地址仍用于 Host 校验，优选展示不会改变服务监听与访问权限。

## 验证

Node.js 24.5+ 下执行 `npm ci`、`npm test`。`scripts/check-harness.mjs` 使用临时 DSH_HOME、伪凭据及测试专用模型流，实际启动官方 DSH Web、加载插件、生成普通及长原文阅读，验证自动分段、上下文重试、缓存、配置只读和 Key 不返回。其他测试覆盖已有 DSH 热加载接入、独占端口插件不重复激活、HMR 关闭时拒绝创建第二个服务、启动锁、profile 配置保留、缺少 Node/npm、旧 Node、下载校验与清理、依赖自动修复、端口避让及重复启动、已有 DSH 入口复用与缺失提示、输入与来源检查、书库系列、费用、缓存身份与局域网权限。付费模型与真实联网搜索质量需要有效 Key 单独验证。
